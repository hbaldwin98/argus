# Parity spec: Review and agents

Group: review dialog, comment box, history dialog, compose box, sessions dialog, transcript reader.
Requirements a GPUI port must meet, written so it can be ported and tested without reading the TypeScript.
Paths are under `crates/argus-desktop/` unless they start with `DESIGN.md`.

Citation forms: `ts:review/dialog.ts:160` is `page/src/review/dialog.ts` line 160. `rs:review/mod.rs:195` is `src/review/mod.rs`. `proto:` is under `crates/argus-protocol/src/`. `test:` names a Rust test. `scene:` names a `src/screens/mod.rs` scene. `design:` is a DESIGN.md section. Rust line numbers inside long modules are approximate where marked `~`.

`page/src/...` is the TypeScript being replaced. `src/session.rs` is the seam and stays (GPUI.md "The seam"): the port sends `Call`s and renders the latest snapshot `Event`.

## 0. Shared rules (apply to every surface below)

- SHARED-1. The front end never predicts. Every gesture sends a `Call`; a surface changes only when the next whole-snapshot `Event` (`review`, `history`, `sessions`, `rail`) says so. Source: AGENTS.md ("the client never predicts"); `rs:connection/sent.rs` (`Sent<T>` dedups; `reload()` resends).
- SHARED-2. A closed dialog is sent once as `open: false`; the page hides it and drops its draft state. Source: `ts:review/dialog.ts:321-326`, `ts:review/history.ts:168-172`, `ts:agents/sessions_dialog.ts:283-287`; test `the_page_hears_a_dialog_while_it_is_open_and_its_closing_once` (`rs:review/mod.rs:534`).
- SHARED-3. Each body has non-content states drawn in this precedence: loading skeleton bars, then a muted message (`empty`, `notice`, `diffEmpty`), then content. Exception: History's diff tests `diffEmpty` before `diffLoading`. Source: `ts:review/dialog.ts:280-281`, `ts:review/history.ts:93-97`.
- SHARED-4. A snapshot update must keep every scroll offset, which text field has the keys, and that field's caret (at the end). Text typed into a field belongs to the field once drawn: Rust's echo of a letter can land after the next letter and must not overwrite it. Source: `ts:review/dialog.ts:125-129,327-331,373-386`, `ts:review/history.ts:134-137,250-255`, `ts:agents/sessions_dialog.ts:193-196,376-381`, `ts:agents/transcript.ts:121-124`. In GPUI this means a snapshot never calls `set_value` on a focused field whose text differs only by in-flight typing.
- SHARED-5. After an update the cursor/lit row (`.drow.cursor`, `.rfile.on`, `.hrow.on`, `.frow.on`) scrolls into view with "nearest" semantics: no movement if already visible. Source: `ts:review/dialog.ts:371-372`, `ts:review/history.ts:249`, `ts:agents/sessions_dialog.ts:375`, `ts:agents/transcript.ts:280`.
- SHARED-6. Key routing while a dialog is up (owned by the keymap group, restated because every dialog depends on it). Layers are asked in `LAYERS` order (`rs:keys/keymap.rs:853-880`): Field (focus is in an input or textarea: only that field's own handler runs), ..., Review, History, Transcript, Sessions. A dialog layer holds every key while open and sends the action its places map to (`Anywhere` plus its own place). Actions in `NOT_THEIRS` (`workspace, feature, checkouts, compose, console, toggleConsole, views, palette, settings`) are not sent (`ts:keys/keymap.ts:209-219`). Every other action goes to Rust, except `filter` in History, Sessions and Transcript, which the page handles itself (SHARED-9). Rust ignores cases it has no arm for (`rs:review/mod.rs:202-205`, `_ => {}`). `shortcuts` (`?`) opens the sheet on the dialog's section (`ts:keys/keymap.ts:190-206,397-399`). Review sends `review_action{action}`; History `history_action{action,row:null}`; Sessions and Transcript `sessions_action{action,row:null}` (`ts:keys/keymap.ts:303-310`).
- SHARED-7. While one of these dialogs holds the keys a pane's input does not: opening blurs the pane input, and closing the last one refocuses it only if the pane input had the keys when the dialog took them (`paneHadKeys`) and a pane is shown. Source: `ts:main.ts:43-59`; `rs:keys/keymap.rs` `takes_from_pane` (layers at 861-866).
- SHARED-8. Escape order: the first layer whose `escape` hook says it held it wins (`ts:keys/focus.ts:49-51`). A menu a dialog opened (the sessions filter menu) hears Escape before the dialog, or the dialog would close and leave the menu standing (`ts:keys/keymap.ts:389-394`). Ordering trap: in Rust's `LAYERS` the Menu layer comes after Sessions (`rs:keys/keymap.rs:861-870`), so a port that follows `LAYERS` alone gets this wrong; for Escape the Menu layer must be asked ahead of the dialog layers.
- SHARED-9. The `filter` action (`/`, and Ctrl-f in the reader) is handled by the page in History, Sessions and Transcript, which focus their field locally; nothing is sent to Rust. Only the Review, which has no page-side filter handler, sends `filter` (Ctrl-P) to Rust (REVIEW-13). Source: `ts:keys/keymap.ts:304-310,402`.

### gpui-kit mapping (each page fetched; "undocumented" means the page does not say)

- Shell: `Dialog` (https://gpui-kit.com/component/dialog.md: `open_dialog`, `title`, `footer`, `w`/`max_w`/`h`, `keyboard(bool)` for Esc, `overlay_closable`). It states width and height are capped at the viewport minus 16 px, shows no full-size preset, and leaves `on_close` and focus trapping undocumented. Set `keyboard(false)` and let Rust's keymap own Escape (REVIEW-33 ordering); a near-window size via `w`/`h` is allowed. `Sheet` is a side panel and does not fit.
- File list: `List` (list.md: `ListState`, `ListDelegate`, `ListItem.selected`, `ListEvent::Select/Confirm`, `scroll_to_item`, `set_selected_index`, `render_empty`). Key bindings and double-click are undocumented; keys are Rust's anyway, so use List for rendering, click and scroll only. Row content (name over folder, counts) is custom `ListItem` content.
- File-list and diff split: `Resizable` (resizable.md: `h_resizable`, `resizable_panel().size().size_range()`, `ResizableState::sizes()`; no persistence). The split is not user-resizable today, so a fixed panel is enough.
- Diff body: custom. gpui-kit has a `Diff` component (https://gpui-kit.com/component/diff.md: `DiffFile::parse(patch)`, `DiffState`, `DiffMode::Split|Unified`, `on_line_click`, `DiffAnnotation` + `render_annotation`, built-in folds with expand buttons, virtualised). It does not fit, for these reasons: it parses patch text instead of taking `DiffRow`s; its keyboard selection (Shift+Up/Down over source lines, Home/End), Shift-click range selection on line numbers, `set_selected_lines` and Selection events belong to the component, not to the review's cursor, range and picking (REVIEW-27, REVIEW-29); its folds are its own, not daemon `ReviewContext` splices; its highlighting is detected from the path or `DiffFile::with_language`, and the daemon's spans (the contract in `design:Review`) may not be fed (unconfirmed: a "No public token or span API" limit). `on_line_click` reports the line's position and the click event, so modifiers are available; whether it fires for fold rows is not documented. Render `Vec<DiffRow>` with `v_virtual_list` (virtual-list.md: `v_virtual_list`, `Rc<Vec<Size<Pixels>>>` item sizes, `VirtualListScrollHandle::scroll_to_item/offset/set_offset/scroll_to_bottom`). The docs give no guidance on keeping the offset when sizes are replaced, so the port saves and restores it itself (REVIEW-35). The comment box is a variable-height item in that list.
- Side and view radios: `ButtonGroup` (button.md: `.child`, `.selected(true)`, `on_click` receives selected indices; single-select default is not stated) or two `Button`s with `.selected`. There is no separate `Toggle` documented.
- Branch chip: `Tag` (tag.md: display only, no click, closable or selected state; fine for the chip, not for the radios).

### gpui-kit mapping

- Body: `MessageScroller` (https://gpui-kit.com/component/message-scroller.md: `MessageScrollerState::new(item_count, cx)`, `is_following_tail`, `scroll_to_item(index, cx)`, `scroll_to_end`, `reset`, variable heights measured by GPUI) or `v_virtual_list` (virtual-list.md: `scroll_to_item(index, Top|Center)`, `offset/set_offset`, but per-item sizes must be supplied, which variable-height entries lack). MessageScroller starts following the tail (matches TRANSCRIPT-10a), but its docs name no "item at the top" strategy (10b says only that `scroll_to_item` "navigates") and say "Any API to save or restore a scroll offset" is not documented (10c) (unconfirmed: the doc has no persisted scroll-offset API, but shows an index-based restore through `scroll_to_item(saved_index)`). Use it for the tail rule and test 10b and 10c; fall back to custom if they fail.
- Entry text: plain styled text with highlight, or `TextView` (text-view.md: `TextView::markdown`, `TextViewState::set_range_highlights` over UTF-8 byte ranges, `reveal_range`, `selectable`; no plain-text constructor documented). - Find field: `Input`. Copy: GPUI `ClipboardItem` driven by Rust's `Then::Copy`; `Clipboard` (clipboard.md: plain-text copy button with `value`/`value_fn`/`on_copied`) is a button, not the Rust-driven path.

- Split: `Resizable` or a fixed panel.
