# Parity spec: cross-cutting rules

What the four group specs (`shell.md`, `board.md`, `checkouts-code-views.md`, `review-agents.md`) leave between them: rules that no single surface owns, because they span surfaces, the connection, or the window. Read this after the group specs; it restates a group rule only where it has to tie two of them together, and cites that rule by id. Companion to `GPUI.md` (scope).

## How to read this

- **Paths** follow `shell.md`: `ts:X` is `crates/argus-desktop/page/src/X`, `rs:X` is `crates/argus-desktop/src/X`, `css:N` is `crates/argus-desktop/assets/style.css` line N, `html:N` is `crates/argus-desktop/assets/index.html` line N, `scene:name` is a scene of `rs:screens/mod.rs`.
- **Ids.** `CROSS-<n>`, stable. Where today's page and its docs disagree, or the page does something that looks like an accident, a **Gap** line says so; the port decides, this spec does not.
- **Coverage check made for this file.** Every source file under `page/src` and `src` was matched against the four specs. The only modules none of them cites are `rs:connection/daemon.rs` (CROSS-1..4), `rs:extensions/keys.rs` (CROSS-17) and `rs:screens/live.rs` (CROSS-27); the rest are `mod.rs` group headers and `rs:fixtures.rs`. Every one of the 44 scenes in `rs:screens/mod.rs:1848-2108` is cited by at least one spec (`switcher` only by `shell.md`).

## CONN: the connection's life, as every surface sees it

- CROSS-1. **The window owns no daemon.** It runs `argus bridge` (or `ssh <host>` with the bridge's arguments) as a child, speaks the protocol over its stdin and stdout, and never opens the socket or starts `argusd` itself. A bridge started from a window must not flash a console (`CREATE_NO_WINDOW` on Windows). `argus` is looked for beside the executable before `PATH`, so a bundled sidecar beats an older install. (`rs:connection/daemon.rs:1-10,195-215,224-235`)
- CROSS-2. **Connecting loop.** A failed round (the bridge could not run, or closed before the daemon said a word) sets the status to connecting with the bridge's last 16 KiB of stderr as the reason (SHELL-STAGE-11's `detail`), then waits **2 s** before the next round. A daemon from before the greeting is reached again at once without a greeting. A connection that closes without `Stopping` goes back to connecting **at once** and keeps trying; one that closed after `Stopping` goes to stopped and waits for Reconnect (SHELL-STAGE-14) with no retry at all. (`rs:connection/daemon.rs:30,99-143`)
- CROSS-3. **Protocol mismatch is carried on with.** A daemon that refuses this window's protocol still counts as connected: the opening it sent is applied and the foot raises the alarm (SHELL-FOOT-2) naming both protocols and `argus server restart`. Nothing else in the window is disabled by it. (`rs:connection/daemon.rs:165-180`)
- CROSS-4. **Switching host** (`set_host`, from the switcher or the connecting stage's `Use this machine`) aborts the current loop, drops its bridge (which kills the child) and starts a loop for the next host. Before the new daemon answers, the window **forgets** the last one: the tree and consoles are emptied, `loaded` goes false (so every stage shows the connecting card, SHELL-STAGE-11), queued alerts are cleared and a pending chime is dropped. A host equal to the current one is no change. A blank host means this machine. (`rs:connection/daemon.rs:85-97`, `rs:connection/shared.rs:139-144`, `rs:session.rs:271-289`)
- CROSS-5. **A lost connection keeps the last tree on screen, undimmed.** While connecting after having been connected, `loaded` stays true: the rail, stage, dialogs and panes go on showing what the last daemon said, and nothing on screen says it is stale except the foot's dot (SHELL-FOOT-3). Only **stopped** dims the heading, rail and strip (SHELL-STAGE-14, `ts:chrome.ts:61-64`). Every gesture made meanwhile is dropped, not queued (SHELL-SEAM-16): a button press, a typed key into a pane, a review comment. (`rs:session.rs:256-261`, `rs:connection/shared.rs:107-109,161-170`) **Gap:** no surface tells the person their press went nowhere; the port decides whether to dim or disable controls while connecting, but must not queue (a queued gesture would reach a different daemon, CROSS-4).
- CROSS-6. **What a new connection resets, for every surface at once** (`Session::connected`, in this order): the status takes the greeting and alarm; any **page** open over a stage (an agent view or an extension page) closes without a notice; extension views, extension keys and extension dialogs are cleared (the new daemon re-sends its own); what this window reported or asked of the last daemon is forgotten (`reported`, `awaited` request ids, the features asked for, a Code or review comment awaiting its save); the sessions cache and the older-daemon translator are reset; then the opening messages are applied; an **open Sessions dialog asks again** (or says it cannot); an **open add-project dialog** drops its in-flight add and preview and browses its current folder again; every **shown pane is subscribed again** and the keys are re-settled; agent views and saved views are asked again when the daemon can, and saved views are **cleared** when it cannot. Dialogs not named here (review, history, link, reconcile, rename, palette, settings) stay open on their last snapshot and refresh only when the daemon next says something. (`rs:session.rs:301-349`; `rs:chrome/add_project.rs:280-285`; `rs:panes/shown/mod.rs:386-394`)
- CROSS-7. **A comment in flight across a reconnect.** A comment box waiting for its save (REVIEW-AGENTS-COMMENT-9, the Code stage's) forgets what it sent on reconnect; whether the box then reopens for a resend or is lost is decided by `forget_sent_comment(s)`. (`rs:session.rs:320-321`) **Gap:** no spec states what the person sees; a port test must pin it before the port.
- CROSS-8. **Stopped holds no keys.** The stopped card is an `alertdialog` over the window (`html:138-145`) but there is no key layer for it (SHELL-KEYS-10 lists none): keys still reach the stage, a pane's text area and every dialog under it, and their calls are dropped (CROSS-5). The pointer is blocked by the card's scrim, except where CROSS-21's stacking puts something above it. Reconnect is honoured only while stopped. (`ts:keys/keymap.ts:280-381`, `rs:connection/shared.rs:151-155`)

## CAP: an older daemon

- CROSS-9. **Every capability gate is read live from the greeting**, so a daemon restarted to a newer build enables the surface on the next connection with no window restart, and an older one disables it again. Gates and what each does when the daemon lacks it: `AGENT_VIEWS` (views not asked), `SAVED_VIEWS` (saved views cleared, none asked), `VIEW_ACTIONS` (an agent view's buttons drawn disabled, CHECKOUTS-CODE-VIEWS-AGENTVIEWS-12), `PASTE_FILE` (`argusd is too old to paste files`), `RENAME_PANE` (SHELL-RENAME-3), `ADD_PROJECT`, `CONSOLES` (console not offered), `CODE` (CHECKOUTS-CODE-VIEWS-CODE-2), `FILES` (Files panel), `FOCUS` (the window's focus not reported), `REQUEST_REFUSALS` (CROSS-10). (`rs:session.rs:339-346,359,830,1243,1337,1393,2080,2189,2508,3081,3124,3155,3161`)
- CROSS-10. **Refusals are heard one way.** A daemon that predates `REQUEST_REFUSALS` has its old error messages translated into this build's refusals (`OlderDaemon::read`) before any surface sees them, so each surface handles one refusal shape. The translator is reset on every connection (CROSS-6). (`rs:session.rs:355-361`)

## FOCUS: who has the keys when one surface covers another

- CROSS-11. **One focus-return rule per overlay, as today.** The group specs state each overlay's own rule; together they are:

  | Overlay | Takes the keys on open | Gives them back on close |
  |---|---|---|
  | Palette, sheet, settings | yes (field / close button) | to what had them (SHELL-PALETTE-1/2, SHELL-SHEET-1, SHELL-SETTINGS-1) |
  | Add-project, link, reconcile, review, history, transcript, sessions | yes; blurs the pane | to the pane only if it had them and a pane is shown (SHELL-SEAM-10, SHARED-7) |
  | Extension question | only when `prompted` | never takes them otherwise (CHECKOUTS-CODE-VIEWS-EXTDIALOG-7) |
  | A menu | its first enabled item | **nowhere**: `closeLayer` empties the layer and focus falls to the document (`ts:kit/menu.ts:22-24,38`) |
  | Rename | its name field | **nowhere** stated (`ts:panes/rename.ts:61`) |

  **Gap:** after a menu or the rename dialog opened from a pane that had the keys, the keys do not come back to the pane: the next key goes to the stage layer. In GPUI the default is the opposite (`focus_lost_restore_target`, SHELL-SEAM mapping); the port decides and writes one rule for every overlay rather than one per surface.
- CROSS-12. **Overlays over overlays.** Opening the palette, sheet or settings closes the other two (SHELL-KEYS-13) but **not** a dialog: settings can open over the review, and its "return to what had it" lands on the review's field, after which closing the review returns the keys to the pane by SHARED-7. A menu opened from a dialog hears Escape before it (SHARED-8). A port must keep a stack, not one "previous focus" slot, or these chains break. (`ts:keys/keymap.ts:168-182,389-394`)
- CROSS-13. **No focus trap.** No dialog uses `<dialog>`/`showModal` or `inert`; dialogs are `role="dialog"` divs (`ts:agents/sessions_dialog.ts:315`, `ts:board/tracker/link.ts:235`, `ts:checkouts/stage.ts:587`, `ts:chrome/projects.ts:530`, …). The browser's own **Tab** therefore walks out of an open dialog into the controls under its scrim; Tab is bound only after the leader in a pane (`rs:keys/keymap.rs:556`). `audit.mjs` tabs through every control but asserts no order. **Gap:** GPUI has no implicit Tab order (each control needs a `tab_index`/focus handle); the port must choose an order per surface and whether dialogs trap, and no spec states either.
- CROSS-14. **Focus rings.** Programmatic focus is "without a ring" in several places (SHELL-SHEET-1/8, SHELL-SETTINGS-1) and the stylesheet draws rings only on `:focus-visible` (23 rules). The rule a port must keep: a ring appears after a keyboard move, never after a click or an open.

## KEYS: what spans the keymap and the surfaces

- CROSS-15. **Keys outside a pane that only the webview answers.** Outside a pane's text area the page prevents default only for keys a layer binds (`ts:keys/keymap.ts:386-406`). Every other key reaches the webview: `Ctrl C` copies selected text, `Ctrl A` selects the page's text, and the webview's own accelerators (reload, find) are not suppressed. Inside a pane every key is prevented (SHELL-INPUT-2). **Gap:** GPUI gives none of these; the port keeps copy of selected text (CROSS-16) and drops reload.
- CROSS-16. **Selectable text everywhere but chrome.** Any text not marked `user-select: none` can be dragged over and copied, by `Ctrl C` (CROSS-15) or by the right-click `Copy` menu SHELL-MENU-5 offers for a selection. Chrome is excluded: the rail brand row, key cards, the code ruler, the diagram marks, and the whole body while a float moves, a panel drags or a sash is held (`css:3064,4565,4614,4826,6148,6780,8336,9782`). What a person copies this way today: transcript turns, view text and markdown, review and history diff lines, notices, the shortcuts sheet. **Gap:** GPUI divs are not selectable; no group spec lists text selection outside the terminal as a requirement. The port decides which surfaces get a selectable text element.
- CROSS-17. **Extension keys, Rust side.** An extension chord matches as a keymap chord does (a character carries its own shift) except that it **never matches with Meta held**; after the leader in a pane only commands scoped `anywhere` or `pane` run; the sheet gives each extension one heading `Extensions · <name>`, listing `anywhere` and `pane` commands with and without the leader, `checkout` and `view` commands as `(on a checkout)` / `(in <view>)`, each view as `Go to <title> (the sidebar's Extensions, or the palette)` with no key, and each view action's key as `<label> (in <view>)`. Extension keys are cleared on every connection (CROSS-6). (`rs:extensions/keys.rs:74-102,130-163`; tests `after_the_leader_only_a_command_heard_anywhere_or_on_a_pane_runs`, `an_extensions_keys_are_one_heading_of_the_sheet_and_every_command_is_in_the_palette`)

## POINTER: every drag, one discipline

- CROSS-18. **Today's drags disagree in four ways**, and the port should pick one rule per column rather than copy each:

  | Drag | Starts after | Escape cancels | Release heard | Survives a redraw from Rust |
  |---|---|---|---|---|
  | Panel to a dock (SHELL-PDRAG) | 5 px | yes | window, capturing | not stated |
  | Pane header in the grid (SHELL-GRID-11) | 4 px | yes | window | yes (`busy`) |
  | Grid gutter (SHELL-GRID-8/9) | press | no | window | yes (`busy`, then held) |
  | Edge sash (SHELL-EDGE) | press | no | window | yes (held width) |
  | Float move/resize (SHELL-FLOAT-4) | press | no | window, capturing | yes (`held`) |
  | Board card (BOARD-DRAG-2) | 6 px | no | window | yes (re-dressed, BOARD-DRAG-6) |
  | Sequence diagram pan (BOARD-SEQ) | 5 px | no | pointer capture | not stated |
  | Figure pan (CHECKOUTS-CODE-VIEWS-FIGURE) | 4 px | no | pointer capture | not stated |
  | Code ruler (CHECKOUTS-CODE-VIEWS-CODE) | press | no | pointer capture | not stated |

  (`ts:layout/drag.ts:19,114,155,161`, `ts:panes/split.ts:49,287-303,365,388`, `ts:layout/edge.ts:23-56`, `ts:layout/floats.ts:98-104`, `ts:board/feature_stage.ts:823`, `ts:board/lenses/sequence.ts:590,632`, `ts:views/blocks/figure.ts:22,185,199`, `ts:code/stage.ts:497-501`)
- CROSS-19. **The click after a drag is the drag's.** PDRAG and the board each swallow the one click a release would produce (SHELL-PDRAG-1, BOARD-DRAG-8); the other drags that start on a clickable element (a pane header, a dock tab) rely on the same rule. A port's drag must consume its release, or every drag that ends on a button presses it.
- CROSS-20. **Nothing resizes a pane mid-drag.** Every sash and gutter drag marks the body `resizing`, and every screen waits for it to lift before reporting its size (SHELL-EDGE-1, SHELL-GRID-9, SHELL-SCREEN-11), so a child program is resized once per drag, never per frame. A GPUI port must keep one "a resize is held" flag the screens read, across the rail, docks, outline, code columns and grid alike.

## STACK: what draws over what

- CROSS-21. **Stacking order today**, back to front, from the z-index tokens (`--z-raised 2`, `--z-layer 3`, `--z-sash 4`, `--z-modal 5`, `css:902-905`) and fixed values: the stage and docks; sashes (4); the narrow-window right-dock drawer (20, `css:10458`); dialogs' scrims (`.review-layer .scrim` 5, `css:6589`), menus (`.layer` 5, `css:4502`) and extension questions (5, `css:8763`), ties broken by DOM order (`html:128-138`: review layers, then the menu layer, then extension questions); the palette, sheet and settings (`.layer.over` 6, `css:6284`); an opened figure (7, `css:9735`); the stopped card (8, `css:3684`); the notice line (9, `css:3718`); floats (30, `css:4590`); the panel drag's preview and ghost (60, 61, `css:4832,4859`). No ancestor makes a stacking context (`.app`, `.stage`, `.work` are only `position: relative`, `css:2281-2287,2973-2978,4579-4584`). **Gap:** as written, a floating saved view (30) draws **over** menus, dialogs, the palette, settings and the stopped card, so a dock menu opened from a float's own head would be hidden under it, and the float stays clickable while stopped. The notice also draws over the stopped card. The port must decide the order on purpose; `GPUI.md`'s `Root` mounts dialogs and notifications in its own layers, which gives a different order by default.

## LOOK: changes that repaint every surface

- CROSS-22. **One theme value, every surface.** The stylesheet's tokens repaint every DOM surface on a theme change for free. The surfaces that **cache** a colour or a measure and must be told: the terminal screens (palette re-read and repaint, SHELL-SCREEN-13; `ts:panes/screen.ts:384-387,395-400`); the Windows border (SHELL-TITLE-6) and Mica's tint (SHELL-LOOK-5), both repainted by `dress` (`rs:connection/commands.rs:79-84`); the font picker's default-face name (SHELL-FONT-5); the settings' marked theme card (SHELL-SETTINGS-6). `system` follows the OS light/dark in each of these separately (`ts:panes/screen.ts:384`, `ts:settings/preferences.ts:135`). In GPUI every surface reads the theme at paint, so the cached list becomes one observer of the window's appearance; nothing may keep a copy of a colour.
- CROSS-23. **Font and zoom re-measure what depends on a cell or a line.** A changed mono family, zoom or pixel ratio re-measures every terminal cell and re-reports every side's grid (SHELL-SCREEN-13, SHELL-LOOK-4/6); the grid's least pane size follows the cell (SHELL-GRID-8). The Capture note's line-number gutter is measured from a hidden copy of the note and is realigned only on its own events (an edit, a scroll, a redraw of the note) (`ts:board/capture.ts:42-60,77,90,95,132`). **Gap:** a window resize, a zoom or a font change leaves the Capture gutter misaligned until the next keystroke; GPUI's text layout should make the gutter follow without a rule of its own.
- CROSS-24. **Zoom scales every length, stored lengths do not move.** Zoom is the webview's own (`rs:connection/commands.rs:69-75`), so every CSS pixel scales: fonts, terminal cells, the drag thresholds of CROSS-18, PDRAG's 160/560/320 px, the float's 96/64/28 px steps and 120/40 px clamps, and the stored dock, float, rail and column sizes (all kept in CSS px in `desktop.json`). The **width breakpoints** are CSS px too, so zooming in narrows the window as the layout sees it: at 200 % a 2000-px-wide window is laid out as 1000 px and gets the rail folded and the drawer dock (CROSS-25). A GPUI port must apply zoom as one scale over logical pixels, convert pointer positions back before sending a size or bounds, and evaluate breakpoints in the scaled width.
- CROSS-25. **Every width-dependent rule, in one list**, because each group spec names only its own: window ≤ 1200 px: rail folded to icons with no sash, right dock as a drawer over the stage, the strip's status chip shown, the feature index's filter folded into a toggle (`css:10251-10275,10440-10460,3306,10494`; SHELL-STAGE-15, BOARD-INDEX-6); ≤ 1100 px: the strip's grid size hidden, the history columns 360 px, the transcript's turn list narrow (`css:3311,6961,7134`); ≤ 1060 px: the checkouts side column hidden (`css:5370`); ≤ 640 px: a timeline's lanes stack (`css:9351`). By the **container's** width rather than the window's: an extension table drops optional and trailing columns at 620/560/540/460 px and folds its row buttons into `⋯` at 560 px (`css:7903-7925,8721-8730`; CHECKOUTS-CODE-VIEWS-EXTVIEW-4/31); the rail draws icons at ≤ 120 px (`css:10268`; SHELL-RAIL-33). A view docked in a narrow dock therefore lays out unlike the same view as a page: the port needs container-width layout, not only window-width.
- CROSS-26. **Reduced motion.** With the OS's reduced-motion set, the loading bars' shimmer, the spinner, the working dot and a changed view's highlight do not animate (`css:2262,3673,3752-3758,9857,9868-9872`). No group spec states it; GPUI does not read the setting for you.

## PREDICT: the "client never predicts" rule, audited across groups

- CROSS-27. **What the page may hold ahead of Rust, and nothing else.** Read with each group's *Page-held state*: (a) text being typed in a field, which wins over Rust's echo of it (SHARED-4, BOARD-FORM-8, SHELL-FONT-5, SHELL-SETTINGS-5); (b) a gesture in progress (every drag of CROSS-18, a slider held); (c) a size let go at, **until Rust answers** (SHELL-GRID-9's held shares, released after 600 ms; SHELL-EDGE's held width); (d) view state with no daemon meaning (scroll, highlight, folded rows, menus, the picked rail row). A request's **result** is never drawn before Rust says it: a moved card goes back until the board says it moved (BOARD-DRAG-7), a renamed pane keeps its name (SHELL-RENAME-3), a setting draws what Rust sends back (SHELL-SETTINGS-4). A port test for any `Call` that the daemon can refuse: refuse it, and the view is unchanged.
- CROSS-28. **A held width can outlive Rust's answer.** After the rail's sash is let go, Rust forgets what it last sent of the rail so the clamped width always comes back, even when it equals the old one (`rs:session.rs:802-808`). The outline, brief, code-tree and code-outline sizes travel in the same `rail` event (`rs:session.rs:3255-3259`) but their calls do **not** forget it (`rs:session.rs:809-824`). **Gap:** drag the outline past its 1200 px bound while it already sits at 1200, and Rust's value does not change, nothing is sent, and the page keeps drawing the width it predicted until some other change resends the rail. Same shape to check for the dock sizes (`DockGesture::Size`, SHELL-DOCK-13). The port should make "a release always gets an answer" one rule for every sash.

## TIME: relative times

- CROSS-29. **Nothing ticks.** Every "ago" and "resumed" text is computed when its surface is drawn (`ts:kit/clock.ts:35`, `ts:views/values.ts:64`, Rust's `rail(now)` at `rs:session.rs:3125`), and the only periodic work in the window is the 16 ms frame tick, which sends terminal rows only (`rs:main.rs:139-146`). So `3m ago` on the rail, a session row or a view stays `3m ago` until something else redraws that surface. **Gap:** no spec says whether the port should refresh relative times on a timer; today it does not.

## CLIP: one clipboard

- CROSS-30. **Three page-side writers and one Rust writer.** OSC 52 (`ts:main.ts:109-111`), the selection menu's `Copy` (`ts:kit/menu.ts:95`) and the Record lens's ADR copy (`ts:board/lenses/work.ts:985`) write through `navigator.clipboard`; a pane's drag, a view's copy button and `take_copied` write through Rust (SHELL-SYSTEM-3). The page-side ones fail silently, the Rust ones say `could not copy: <err>`. In the port every write goes through Rust's `system::clipboard` and every failure says the same notice.

## SCENES: what the port's harness has to replace

- CROSS-31. **A scene's page step is a CSS selector.** `Step::Click` names a selector the page clicks after replaying the events (`rs:screens/mod.rs:1760-1766`); the only use is `switcher`'s `#heading .projbtn` (`rs:screens/mod.rs:2105-2108`). The port's scenes need an element id in its place, and the switcher scene stays page-held state (`menuOpen`, SHELL-SEAM page-held state) the port must set without a click if it keeps scenes as data.
- CROSS-32. **Live scenes answer through the same stand-in daemon.** `serve_screens` builds a scene and answers each call the page makes against it, with the same `answer` the static scenes use (`rs:screens/live.rs:1-16,54-80`), which is how `audit.mjs` gets real answers to clicks. A GPUI port drives `Session::call` in-process instead, so the HTTP server goes, but the stand-in daemon (`answer`, `Window`, `rs:screens/mod.rs:1768-1810`) is the fixture every port test of CROSS-6 and CROSS-27 needs.
- CROSS-33. **States no scene shows, across groups:** connecting **after** a tree was loaded (CROSS-5), a host switch in progress (CROSS-4), a protocol alarm (CROSS-3), a dialog open while stopped, an overlay over an overlay (CROSS-12), any window narrower than 1200 px (CROSS-25), a zoom other than 100 % (CROSS-24), the light theme (every scene is drawn in the default `system` theme of the machine that shoots it), and reduced motion (CROSS-26).

## Decided

The person settled these on the feature board (decisions #49-#55); a port
builds the decided behaviour, not today's where they differ.

1. While connecting after a loss (CROSS-5), the window dims the tree, disables actions and says Reconnecting in the sidebar foot, as it does when stopped.
2. Closing any overlay gives the keys back to what had them, the pane included (CROSS-11).
3. Modal dialogs trap Tab; the extension dialog that leaves focus in the pane stays non-modal (CROSS-13).
4. Text is selectable only in the terminal, diffs, the Code stage, transcripts and markdown blocks; ids and paths get copy buttons (CROSS-16).
5. Stacking from the bottom: floats, menus and popovers, dialogs, the stopped card and notifications (CROSS-21).
6. One 5 px drag threshold, and Escape cancels any drag (CROSS-18).
7. Relative times repaint on a 30 s tick (CROSS-29).
