# Parity spec: Board (feature stage, lenses, tracker dialogs, capture)

Requirements a GPUI port must meet, written so a surface can be ported and tested without reading the TypeScript. Describes behaviour, not CSS.

## Conventions

- Paths are relative to `crates/argus-desktop/`. `ts:` is `page/src/board/...` unless it starts `page/`. `rs:` is `crates/argus-desktop-core/src/...` (not relative to `crates/argus-desktop/`); `tauri:` is `crates/argus-desktop/src/...`.
- A behaviour id is `BOARD-<SURFACE>-<n>`. Surfaces: INDEX, LIST, COLS, DRAG, PEEK, MENU, KEYS, CAPTURE, HEAD, WORK, FORM, RECORD, FLOWS, SEQ, LINK, RECONCILE, TICKETS.
- "Call" means a `connection::page::Call` variant (rs:connection/page.rs). The page's `call('snake_name', ...)` is the same Call. The port keeps `Session::call(Call)` as the only way a gesture reaches the app; the client never predicts a result (AGENTS.md: "the client never predicts the result of a request"). Every "shows when the pushed board says so" rule below is that rule.
- Source tags: `DESIGN` = DESIGN.md "The feature view" (line ~2183), "Sequence diagrams" (~2267), "What a feature row says" (~2292), tracker paragraphs (~2370-2410, ~2571-2582). `DESKTOP` = DESKTOP.md "Decided for later slices" (line 372). Tests are cited by name and file.
- Surfaces whose state is built wholly in Rust today (the `*Page` structs, `Features`, `FeatureView`, `CapturePage`, `LinkPage`, `ReconcilePage`) keep that: the port reads the same snapshots (GPUI.md "The seam", step 1). Where the page keeps its own state (form drafts, expanded diagram, legend, scroll cue, drag) that state moves into the GPUI view and is listed under "Page-side logic".

## Read-this-first discoveries (spec bugs and traps found while reading)

1. **Held and Archived order disagree.** The board draws the side column as Held over Archived (ts:feature_stage.ts:612) but Rust steps `j`/`k` through `COLUMNS = [Queued, Active, Done, Archived, Held]` (rs:board/features.rs:72; test `the_board_steps_column_by_column_and_skips_the_folded_archived`, feature_stage.rs:1024). So with both columns shown, `j` from the last Done card lands on Archived (the lower box) before Held (the upper). DESIGN and DESKTOP both say "then Archived and Held". The port must choose one order for drawing and stepping; this spec records both as they are (BOARD-COLS-4, BOARD-KEYS-3) and the choice is a human's.
2. **Escape on the bare index does nothing.** `features` has no `escape` hook (page/src/keys/keymap.ts:356), unlike `outline` and `capture`. DESIGN says Esc climbs from the index to the workspace, but the desktop does not.
3. **Copy as ADR bypasses Rust.** `copyRecord` writes the clipboard from the page with `navigator.clipboard` and raises its own notice (ts:lenses/work.ts:984-989). `Call::CopyText { text }` exists and should be used.
4. **`select_work` on a row Rust no longer has** is accepted and stored; `work.rs` then draws the first row (rs:board/lenses/work.rs:26-28). The port must not clamp itself.
5. **The Flows lens and the expanded diagram scale the picture in the page** from measured pixel widths (ts:lenses/flows.ts:213-241, sequence.ts:275-287). That is layout, not data; it has no Rust twin.

## INDEX: the index frame, strip, filter, fold, states

Sources: ts:feature_stage.ts:144-338; rs:board/features.rs; rs:board/feature_stage.rs; DESIGN "The feature view".

- **BOARD-INDEX-1** With no repository chosen (`Features.repository` empty or no `Features`) the stage shows an empty state: folder icon, "No repository", "Choose one on the left." (ts:feature_stage.ts:161-170).
- **BOARD-INDEX-2** Until the board arrives (`loaded == false`) the stage shows the head (filter field) and six skeleton bars of widths 50, 80, 65, 75, 55, 70 percent (ts:feature_stage.ts:173-177). `loaded` is true only once `BoardFollower` holds the board (rs:board/features.rs:129; test `a_board_not_yet_arrived_is_not_loaded`).
- **BOARD-INDEX-3** With the board loaded and `active+queued+done+held+archived == 0` the stage shows: "No features in <repository> yet", the text "Agents open them with `argus-hook feature open`, or write one as a note with" a keycap `N`, and a primary "New feature" button that sends `Call::Capture { gesture: Open }` (ts:feature_stage.ts:178-198). The filter field stays above it.
- **BOARD-INDEX-4** Otherwise the stage shows head, then the board or the list per `Features.layout`, then the key bar (ts:feature_stage.ts:199).
- **BOARD-INDEX-5** The title strip (outside this group's files, but fed by `featuresStrip`) carries, when a repository is chosen and no feature is open: the counts "N active · N queued · N done" (a count of 0 is omitted; active is attention-coloured, done ok-coloured; held and archived are not counted there); a tooltip on the counts "N new · Enter open · V list or board · M move to… · G go to its pane"; a two-segment radio "List | Board" (the current one marked) whose click sends `Call::SetLayout { layout }`; a filter-toggle icon button; and a primary "New feature" button (ts:feature_stage.ts:217-276). With a feature open the strip instead carries that feature's lens tools (BOARD-HEAD-9), and with no repository it carries nothing.
- **BOARD-INDEX-6** The filter-toggle button appears only when the window is under 1200px wide (the field folds into it, ts:feature_stage.ts:259). Clicking it toggles a "filtering" mode and, on turning it on, focuses the filter field. Leaving the field (Enter or Escape) or blurring it empty turns the mode off (ts:feature_stage.ts:287-297).
- **BOARD-INDEX-7** The filter field has placeholder "Filter by title or #" and aria-label "Filter features". Every edit sends `Call::FilterFeatures { filter }` with the full text (ts:feature_stage.ts:284-286). Rust applies the change, moves the cursor onto a listed feature (the last one chosen whenever the filter lists it) and asks that feature's tasks and flows if the cursor moved (rs:board/feature_stage.rs:324-338; tests `filtering_moves_the_cursor_onto_a_feature_it_lists`, `a_filter_matching_nothing_peeks_nothing_and_widening_it_lands_back_on_the_feature_chosen`, `typing_a_filter_that_still_lists_the_chosen_feature_keeps_it_and_asks_nothing`).
- **BOARD-INDEX-8** While the field has the keys, Enter and Escape both leave it: prevent default, remove "filtering" mode, blur the field so the list has the keys (keymap `Place::Filter` Enter/Escape -> `Leave`, rs:keys/keymap.rs:728; ts:feature_stage.ts:287-293). The filtered list stays filtered.
- **BOARD-INDEX-9** Redraws never lose what is being typed. If the filter field has focus when the index is rebuilt, its text, selection start and end and focus are restored after the rebuild, because the echo being drawn may be older than the last keystroke (ts:feature_stage.ts:129-142, `keepTyped`). In GPUI, keep the field's `InputState` alive across snapshots and never `set_value` from a snapshot while it is focused.
- **BOARD-INDEX-10** A change to the snapshot's `filter` that did not come from typing (a `reveal` that clears it) replaces the field's text when the field is not focused (ts:feature_stage.ts:299, `filter.value = f.filter`). Source of the clear: rs:board/feature_stage.rs:287-290; test `going_to_a_feature_the_filter_hides_clears_the_filter`.
- **BOARD-INDEX-11** What matches: the trimmed, lowercased filter (a leading `#` stripped) is contained in the lowercased title, or equals the number as a string; empty keeps all (rs:board/features.rs:99-103; test `the_filter_keeps_titles_holding_its_words_and_the_number_typed_with_or_without_a_hash`). The filter is not persisted (DESIGN, "A filter ... is not saved").
- **BOARD-INDEX-12** The fold toggle ("Show held and archived N" / "Fold held and archived N", N the folded count dimmed) appears in the head only on the List layout and only when `folded > 0`; it sends `Call::FeatureAction { action: Folded }` (ts:feature_stage.ts:309-317). On the Board the Archived column's own controls do the same (BOARD-COLS-6).
- **BOARD-INDEX-13** What the fold covers: on the list, Held and Archived; on the board, only Archived (Held is a column a card is dropped on) (rs:board/features.rs:90-95; test `the_list_folds_the_held_and_archived_and_the_board_only_the_archived`). `folded` counts those the fold covers that the filter matches, shown or not (test `the_fold_counts_what_it_covers_that_the_filter_matches`).
- **BOARD-INDEX-14** The feature opened from the index is always listed whatever the fold and filter say, so a hold pushed while it is read does not swap it for another (rs:board/features.rs:106-109; test `the_feature_opened_is_listed_whatever_the_fold_and_the_filter_say`).
- **BOARD-INDEX-15** The key bar under the index shows keycaps with words: `N` new, `Enter` open, `V` board (or list, naming the layout it would switch to), `M` move, `G` go to pane; on the Board it also says on the right "Drag a card to Held to set it aside" (ts:feature_stage.ts:323-338).
- **BOARD-INDEX-16** Opening a feature (`Call::OpenFeature { slug: Some }`) draws the work view in place of the index; `Call::OpenFeature { slug: None }` returns to it, still peeking at the feature that was open while the index lists it, otherwise the cursor goes to a neighbour (rs:board/feature_stage.rs:213-227; tests `a_feature_held_while_it_is_open_stays_open_and_closing_it_moves_the_cursor_on`, `an_opened_feature_that_leaves_the_board_closes_rather_than_showing_another`). Opening a slug not on the board does nothing (test `a_feature_not_on_the_board_does_not_open`).
- **BOARD-INDEX-17** While the capture note is open it is drawn instead of the index (ts:feature_stage.ts:149-152).
- **BOARD-INDEX-18** Leaving the Feature stage (`state.rail.stage != feature`) closes the expanded diagram (ts:feature_stage.ts:145-148). Showing the index also clears any form being written (`state.editing = null`, ts:feature_stage.ts:159).
- **BOARD-INDEX-19** The layout is remembered per repository under the primary checkout's path in `desktop.json` (`Settings::layouts`), and a repository with none opens as `Settings` says (`opens_as`) (rs:board/feature_stage.rs:297-312; tests `a_layout_is_remembered_per_repository_and_asks_to_be_saved`, `a_repository_that_remembers_no_layout_opens_as_the_settings_say`, `a_board_pushed_while_another_repository_is_chosen_settles_on_its_own_layout`). Changing the layout moves the cursor off a feature the new layout folds (test `changing_the_layout_moves_the_cursor_off_a_feature_the_new_one_folds`).
- **BOARD-INDEX-20** Scenes: `features-list`, `features-board`. No scene covers no-repository, loading, empty-repository, filter-with-no-matches, or the narrow filter toggle.
- **BOARD-INDEX-21** `Call::GoToFeature { slug }` (a `#` result chosen in the palette, ts:keys/palette.ts:227; rs:connection/page.rs:227; rs:session.rs:2922-2928) takes the Feature stage to that feature: it goes to the stage (the index, whatever feature was open is left), then **reveals** the slug: if the fold hides it the fold is turned on (`show_folded`), if the filter hides it **the filter is cleared** (the field's text is replaced, BOARD-INDEX-10), and the cursor lands on it as a peek and is remembered as the feature chosen (rs:board/feature_stage.rs:279-296). It does **not** open the feature (that is Enter, BOARD-KEYS-8). A slug the board does not hold peeks nothing and the cursor settles on a listed feature (BOARD-PEEK-11). It is the only way into the stage that changes the fold and the filter for the person. Tests `an_archived_feature_gone_to_on_the_board_unfolds_its_column`, `an_archived_feature_revealed_is_listed_and_stays_peeked_past_the_next_board`, `going_to_a_feature_the_filter_hides_clears_the_filter` (rs:board/feature_stage.rs:866,671,958). The palette's own `#` rule is SHELL-PALETTE; `Call::GoToPane` (BOARD-PEEK-7) is the other go-to.

## LIST: the list layout

Sources: ts:feature_stage.ts:340-399; rs:board/features.rs:186-213.

- **BOARD-LIST-1** The list has a label row with columns "(number) Feature, Tasks, Questions, Checkout" and then rows grouped under group labels in the order Rust sends: Active, Queued, Done, Held, Archived (a group label is drawn when `row.group` changes). "New" features are listed with Queued (`group` of a `new` standing is `queued`). Group label colours: Active attention, Done ok, others plain (ts:feature_stage.ts:42-52, 355-366).
- **BOARD-LIST-2** A row shows: `#number` (accent when peeked), title (strong when peeked; muted when its group is done, held or archived), the tasks cell, the questions cell, the branch (monospace, ref-coloured, or faint for quiet groups, ellipsised), and under it the row note (ts:feature_stage.ts:367-390).
- **BOARD-LIST-3** Tasks cell: `new` -> "new"; zero tasks -> "no tasks"; else a progress bar of `round(done/total*100)`% and ` done/total` (ts:feature_stage.ts:71-82). The percent rounding is page-side (see Page-side logic).
- **BOARD-LIST-4** Questions cell: `open > 0` -> "N open" (attention); else `decided > 0` -> "N decided" (ok); else empty (ts:feature_stage.ts:84-88).
- **BOARD-LIST-5** Row note, first match wins: held -> `held: "reason"` (curly quotes); comes-after -> `after #3, #5` (monospace numbers); else next task and agent: `next <label> <text>` then ` · ` then the agent's title and status pill (either may be absent); else `new` -> "nothing written yet"; else group done -> "every task done · archive it to accept it"; else group archived -> "archived"; else nothing (ts:feature_stage.ts:100-123). `next` is present only on the peeked row (rs:board/features.rs:190-193; test `only_the_peeked_row_says_what_comes_next_once_its_tasks_arrive`).
- **BOARD-LIST-6** Agent status pill: a dot and a word tinted by status; word is the daemon's, `waiting` says "needs you" and `needs-review` says "review" (page/src/kit/dom.ts:198-214). Row `agent` is the loudest agent on any checkout of the feature (rs:board/features.rs:247-256; test `the_active_feature_names_its_agent`).
- **BOARD-LIST-7** Mouse on a row: click sends `Call::Peek { slug }`; double-click sends `Call::OpenFeature { slug: Some }`; right-click sends Peek and opens the Move menu at the pointer (BOARD-MENU-1) (ts:feature_stage.ts:370-382). Middle-click and drag do nothing on the list.
- **BOARD-LIST-8** The peeked row is marked current (aria-current) and highlighted. The cursor follows `Features.rows[].peeked`; the list never scrolls itself to the cursor in the page code, but the keyboard steps assume the cursor is visible (see Uncovered).
- **BOARD-LIST-9** Empty list reasons: no filter -> "Every feature here is held or archived."; filter and `folded == 0` -> `Nothing matches "<filter>".`; filter and not `show_folded` -> `Only held or archived features match "<filter>".` (ts:feature_stage.ts:392-397).
- **BOARD-LIST-10** The list sits left of the peek panel (BOARD-PEEK-*) in a split; nothing in the page resizes that split.
- **BOARD-LIST-11** Rows and their order are Rust's: the order is `standing::feature_rows` order after the Listing filter (rs:board/features.rs:112-121). The page never sorts.

## COLS: the board layout

Sources: ts:feature_stage.ts:543-662, 664-747; rs:board/features.rs; DESKTOP "Feature index".

- **BOARD-COLS-1** Columns: Queued, Active, Done as three lanes, then a side stack holding Held above Archived (ts:feature_stage.ts:606-613). Rows arrive in Rust's board order: Queued, Active, Done, Archived, Held, stable within a column (rs:board/features.rs:115-118; test `the_board_lists_its_features_column_by_column_as_it_draws_them`). The page filters the flat `rows` by `group`.
- **BOARD-COLS-2** Column head: coloured dot by group, group name, count. Section label reads "<Group>, N features". The count is the number of cards, except a folded Archived column, which counts `Features.folded` (ts:feature_stage.ts:546-581).
- **BOARD-COLS-3** An empty column says its two lines: Queued "Nothing queued / Written-down features wait here"; Active "Nothing active / A feature moves here when work starts"; Done "Nothing done yet / Lands here when every task is done" (with a settled icon); Held "Nothing held / Drag a card here to set it aside"; Archived "Nothing archived / Drag a card here to accept it" (ts:feature_stage.ts:53-61, 583-594).
- **BOARD-COLS-4** Order discrepancy: drawn Held over Archived; stepped Archived then Held (see discoveries item 1).
- **BOARD-COLS-5** A folded Archived column (`!show_folded`) is one row the width of a column: archive icon, "Archived", the count, a right chevron; click sends `Call::FeatureAction { action: Folded }`. It still takes a dropped card (ts:feature_stage.ts:554-572). Its cards are not listed.
- **BOARD-COLS-6** An unfolded Archived column ends with a "Fold the archived" button sending `Call::FeatureAction { action: Folded }` (ts:feature_stage.ts:595-603).
- **BOARD-COLS-7** Card: top line `#number`, branch (monospace, ellipsised), spacer, corner tag; title; work line; hold line; footer. Corner: agent -> status pill; else comes-after -> "-> after #3, #5"; else `new` -> "new"; else none (ts:feature_stage.ts:678-683, 727-745).
- **BOARD-COLS-8** Card work line: `new` -> "nothing written yet"; zero tasks -> "no tasks yet"; else progress bar, `done/total`, spacer, questions text (as BOARD-LIST-4) (ts:feature_stage.ts:684-696).
- **BOARD-COLS-9** A held card shows a pause mark and the reason (ts:feature_stage.ts:737-743).
- **BOARD-COLS-10** Footer: Rust's `footer` string, e.g. `accepted`, `held`, `every task done`, `<agent> is on it`, `a task started`, `after #3`, `written down`, `written down, nothing in it yet`, then ` · <ago> ago` when the feature or a decision on it has a time. The page splits the text at the last ` · ` only when the text ends with `ago`: the left part is cut with an ellipsis and `· <ago>` keeps its own span so "ago" never wraps alone (ts:feature_stage.ts:664-675; rs:board/features.rs:219-245; test `a_card_says_how_it_came_to_stand_there_and_how_long_ago_it_changed`).
- **BOARD-COLS-11** Mouse on a card: click -> Peek (suppressed when it ends a drag, BOARD-DRAG-8); double-click -> OpenFeature; right-click -> Peek then Move menu at the pointer; left press arms a drag (BOARD-DRAG-1) (ts:feature_stage.ts:703-725).
- **BOARD-COLS-12** Narrow windows: columns keep a minimum width, so the lane row scrolls horizontally. A fade appears at the right edge while more is off to the right, and a chip "N more" with the names of the cut-off columns joined by ` · ` and a right chevron appears (BOARD-COLS-13). The fade shows when `scrollLeft + clientWidth < scrollWidth - 4`; the chip only when also at least one column is cut (ts:feature_stage.ts:625-662).
- **BOARD-COLS-13** A column counts as cut off as soon as any part of it lies right of the lane row's right edge by more than 1px (ts:feature_stage.ts:630-635). Clicking the chip scrolls the lane row smoothly by the first cut column's overshoot plus 10% of the row's width so it clears the fade (ts:feature_stage.ts:636-643). The chip and fade update on scroll and whenever the lane row is resized (ts:feature_stage.ts:655-660).
- **BOARD-COLS-14** The scroll position of the lane row across snapshot redraws is not preserved by the page (the stage is rebuilt every push). The port should keep it (a pushed tree arrives often); the old behaviour is a bug, not a requirement. See Uncovered.
- **BOARD-COLS-15** Scenes: `features-board` only (peeking at `trim`). No scene shows a folded Archived column, a held card, a comes-after card, empty columns, or the scroll cue.

## DRAG: dragging a card to Held or Archived

Sources: ts:feature_stage.ts:749-876; DESKTOP "Feature index"; DESIGN "What a feature row says".

- **BOARD-DRAG-1** A primary-button press on a card records the slug, pointer position and the card's box measured at that moment (ts:feature_stage.ts:714-725). Other buttons do not arm a drag.
- **BOARD-DRAG-2** The drag starts when the pointer has moved 6px or more from the press point (Euclidean distance) while still pressed (ts:feature_stage.ts:823).
- **BOARD-DRAG-3** On start the card is cloned as a floating ghost the width the card had, kept at the same grab offset under the pointer, following the pointer; the card's place in its column is replaced by a placeholder card reading "#N is being dragged" (ts:feature_stage.ts:824-843, 799-806).
- **BOARD-DRAG-4** Which column the pointer is over is hit-tested on the column under the pointer (the folded Archived row counts as the Archived column). When it changes the board is re-dressed (ts:feature_stage.ts:767-771, 839-843).
- **BOARD-DRAG-5** Only Held and Archived take a drop: a column is a target only if the card's row offers that move enabled (`moves` contains `to == group` and no `disabled`). Queued, Active and Done never light up (ts:feature_stage.ts:776-781). A target column is highlighted, gets a drop banner under its header, and the placeholder reads "#N is being dragged to <Column>". Banner text: Archived "Drop to archive: you accept #N as finished"; Held "Drop to hold: you say why #N waits" (ts:feature_stage.ts:783-787, 797-816).
- **BOARD-DRAG-6** A pushed board while dragging redraws the stage plain; the dressing is re-applied after every draw so the drag survives (ts:feature_stage.ts:201, 789-793). The card itself moves only when a pushed board says it did.
- **BOARD-DRAG-7** On release: the ghost goes, the board is redrawn from the last snapshot (the card is back where Rust last put it), and the drop is judged: a drop on the card's own column does nothing (the early return `group === row.group`, ts:feature_stage.ts:869; this also covers a held card dropped on Held and an archived card dropped on Archived); Held sends the hold dialog (BOARD-MENU-7); Archived sends `Call::Archive { slug, archived: true }` (ts:feature_stage.ts:846-876). Reopen/unhold are not drag gestures.
- **BOARD-DRAG-8** The click that follows a release is the drag's and must not peek or open: the page sets a `justDropped` flag cleared on the next tick, which `click` and `dblclick` check (ts:feature_stage.ts:857-861, 704, 707).
- **BOARD-DRAG-9** Dropping on Queued, Active or Done sends nothing and raises a notice: "<Column> follows the work." plus ": <reason>" when the row's move for that column has a `disabled` reason, then a full stop (ts:feature_stage.ts:874-875). Reasons (Rust): Queued "follows the work"; Active "when a task starts or an agent arrives"; Done "when it has tasks and every one is done" (zero tasks) / "when its last task is done" / "when its N open tasks are done"; the card's own column says "here now" (rs:board/features.rs:262-292; test `derived_places_cannot_be_chosen_and_say_why`).
- **BOARD-DRAG-10** Every drag has a keyboard path: `M` (Move to menu), `H` (hold) and `Shift+A` (archive); see BOARD-KEYS (DESKTOP "Feature index").
- **BOARD-DRAG-11** Dropping outside any column cancels with no notice (group is null; ts:feature_stage.ts:863).
- **BOARD-DRAG-12** In GPUI, `ListItem` supports `on_drag`/`on_drop`/`drag_over` (gpui-kit list.md "Drag and Drop Reordering"), which gives the ghost preview and drop-target highlight, but the 6px threshold, the click-suppression and the column hit test need custom code. No test or scene covers any drag today (the audit/shoot scripts do not drag).
- **BOARD-DRAG-13** **Threshold and Escape (decided).** BOARD-DRAG-2's 6 px becomes **5 px**, the one threshold of every drag (cross-cutting CROSS-34, board decision #67), and **Escape cancels** a card's drag (the page has no Escape here): the ghost goes, the board is redrawn from the last snapshot and nothing is sent, as for a drop outside any column (BOARD-DRAG-11).

## PEEK: the panel beside the list

Sources: ts:feature_stage.ts:401-541; rs:board/features.rs:294-376.

- **BOARD-PEEK-1** With no peek the panel says "Choose a feature to peek at it." (ts:feature_stage.ts:451-455).
- **BOARD-PEEK-2** Header line: `#number` (accent), a standing pill (standing words in the pill vocabulary: active -> working, done -> done, held -> waiting, everything else idle, the word shown is the standing itself, page/src/kit/dom.ts:229-232), spacer, `from <branch>` when a branch exists. Then the title, a held line `held: "reason"` (attention), and the brief (muted) (ts:feature_stage.ts:461-475).
- **BOARD-PEEK-3** Under it, the feature's linked tickets as chips (BOARD-TICKETS-1) when there are any (ts:feature_stage.ts:476).
- **BOARD-PEEK-4** Sections, each only when it has lines: "Needs you" (mark `?`, attention head and label), "In flight" (mark half-circle, attention mark, faint label), "Next up" (hollow circle, faint), "Last decided" (check, ok mark, ref-coloured label, muted text) (ts:feature_stage.ts:404-447, 477-480).
- **BOARD-PEEK-5** A line is `<mark> <label> <text>`, with its `aside` (when any) on a second indented line. A line whose label is `◆` is a pane that needs you: icon, title (ellipsised), then the status pill from its aside, with no `?` and no second line (ts:feature_stage.ts:416-447).
- **BOARD-PEEK-6** Rust fills them: Needs you = open, non-withdrawn decisions then agents whose loudest status needs a person; In flight = leaf tasks in `doing`, with the claiming pane's title as aside; Next up = first leaf `todo` task; Last decided = standing decision with greatest `(at, id)` (rs:board/features.rs:299-339; test `the_peek_says_what_needs_you_what_is_in_flight_and_what_is_next`).
- **BOARD-PEEK-7** Footer buttons: primary "Open" -> `Call::OpenFeature`; "Go to its pane" (disabled when `peek.pane` is null) -> `Call::GoToPane { pane }`; spacer; an icon button "..." (aria-label "More: hold, archive, order", tooltip "Hold, archive, or order it after another") opening the Move menu under it with the "Comes after..." item (BOARD-MENU-2). The "..." exists only when the peeked slug is among `rows` (ts:feature_stage.ts:482-511).
- **BOARD-PEEK-8** Peek is fed by the board, which may not list the feature (folded); `peek` is built from all rows, not the listed ones (rs:board/features.rs:156-162). So a peek can show a feature the list hides (after `reveal` unfolds it; test `an_archived_feature_revealed_is_listed_and_stays_peeked_past_the_next_board`).
- **BOARD-PEEK-9** Peeking a feature asks the daemon for its tasks and flows, clears the lens cursors if it is a different feature, and marks it as the chosen one (rs:board/feature_stage.rs:199-208; tests `peeking_asks_for_that_features_tasks_and_keeps_only_them`, `a_cursor_moved_by_a_push_starts_the_lenses_afresh`).
- **BOARD-PEEK-10** Scenes: `features-list` and `features-board` show a peek of `store-faults` and `trim`. Not shown: a held peek, a peek with no branch, with linked tickets, or an agent line.
- **BOARD-PEEK-11** **When what is peeked is hidden by a fold, filter or layout change**, the cursor is not left on a row the index no longer draws: after the fold is toggled (`Folded`, BOARD-INDEX-12), the layout changes (BOARD-INDEX-19) or a board push removes the row from the listing, Rust **settles**: the cursor stays on the feature while it is still listed, else lands on the feature that took its place in the old list (the same position, or the last when the list got shorter), else the first listed; with nothing listed nothing is peeked and the panel says BOARD-PEEK-1 (rs:board/feature_stage.rs:316-346, crates/argus-protocol/src/board/follower.rs:165-182). A cursor moved this way becomes the feature chosen from now on, and a lens cursor or opened feature on the old one is dropped and the feature closes (BOARD-INDEX-16, `settled`). The **filter is the exception**: while it is being typed the choice is remembered, and widening it again returns to the feature last chosen (BOARD-INDEX-7). A reveal (BOARD-INDEX-21) is the only action that opens the fold or clears the filter to keep a feature listed. The peek panel is therefore never about a feature the list hides, except for the moment of a go-to (BOARD-PEEK-8).
